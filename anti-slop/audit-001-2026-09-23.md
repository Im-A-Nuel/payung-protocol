# Payung UI audit, 2026-09-23

Scope: deployed MVP flow, reviewed from the Next.js source and public deployment configuration. No UI code was changed by this audit.

1. HIGH, C-2 Functional Completeness: the purchase path does not show or preflight the buyer's tBNB gas balance. The faucet only supplies IDRP, while `approve` and `buyPolicy` are wallet-sent transactions. A driver can receive IDRP and still fail at the final action because the embedded wallet has no tBNB.

2. MEDIUM, R-38 Real Content: the first-screen CTA says `Masuk pakai Google`, but the configured authentication methods are Google and email. The first screen should state the actual choices and that login creates the testnet wallet required to hold IDRP and receive payouts.

3. MEDIUM, R-26 Interactive Elements: unauthenticated Polis and Riwayat pages only link back to the home screen. They do not offer the available sign-in action at the point where the user needs it, adding an avoidable navigation step.

4. LOW, R-27 UI States: the purchase panel has good loading and API-error feedback, but does not distinguish a missing gas balance from a rejected or failed wallet transaction. A specific next step would be more useful than a generic error.

5. PASS, R-03/R-32: source evidence shows a mobile bottom navigation, 44px or larger main tap targets, semantic buttons/links, and `aria-pressed`, `aria-current`, `role=alert`, and loading labels on relevant controls.

6. PASS, R-17/R-18/R-36: no testimonials, user counts, compliance claims, or unsupported performance claims were found in the reviewed UI source.

## Follow-up, 2026-09-23

The owner requested an immediate UI improvement. Findings 1-4 were addressed in the frontend: the purchase panel checks the native tBNB balance and gives the wallet address when it is empty; the homepage shows zone choices before sign-in; Polis and Riwayat offer sign-in directly; and wallet errors now explain missing gas. The copy also matches Google and email login, first-purchase approvals, and the contract's inclusive rainfall threshold. The changes passed TypeScript and production build checks. Live wallet transactions were not sent as part of this UI review.
